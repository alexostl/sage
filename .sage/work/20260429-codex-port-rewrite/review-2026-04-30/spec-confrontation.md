# Spec confrontation — Codex port rewrite v1 vs prior 6-axis review

## Verdict

**GREEN-WITH-RESIDUAL-GAPS.** Spec.md (post 4-cut version) absorbs the
overwhelming majority of prior review findings — most by genuine
resolution (D6/D10/D11/D12/D13/D14 normalized in §1+§9+§10), the rest
by **principled deferral with named v2 trigger** (§13.2 outcome-harness
signals + §16 sign-off cuts A/B/C/D). The deferrals are not hand-waving:
each cut is paired with an explicit empirical condition that promotes
the work back into scope. However, **three findings from agent-B and
agent-C remain genuinely hanging post-cuts** because they predate the
cuts and the cuts don't address them: (1) the `core/gates/scripts/`
copy step from Claude `bin/sage init` (cap-bootstrap-state) is not in
§4 Stage 7 or 9; (2) the `.sage/constitution.md` user file + preset
merge pattern from `recon-claude-bootstrap.md` is not in §4 Stage 3
(only `__CONSTITUTION_PLACEHOLDER__` injection is); (3) AGENTS.md
generated by Sage instructs `sage_memory_search` (Rule 1A in
`CLAUDE.md`/`AGENTS.md` content) but Cut B removed all MCP
infrastructure — a Codex agent following the generated AGENTS.md
literally on first turn will fail every Standard+ workflow. These are
the three blocking issues. Nothing else rises above non-blocking.

## Cuts vs prior review

The four 2026-04-30 cuts (A=UPS, B=MCP, C=L5, D=hard-tier-1) are
each examined for: (a) did prior review flag the cut surface as
risky? (b) is the deferral documented with a binding v2 trigger? (c)
does any prior finding now hang in the air because the cut's
preconditions vanished?

### Cut A — UPS approval gate deferred (§6.2)

**(a) Prior review flagged?** Indirectly. A1 CC-2 verified UPS
fires correctly; A2 P2 covered tier model defense; A3 documented
approval terminology collision. **None of the 6 sub-agents flagged
the UPS gate itself as risky** — they assumed it would ship and
verified its preconditions. So the cut moves into territory where
prior review didn't push back, which is fine.

**(b) v2 trigger documented?** **YES, three binding triggers:**
phase-jump rate above threshold X% (measured by `turn-audit.sh`
`phase_jump_observed` probe); user-pain rate above Y/week; forge
attempt observed (§6.2 + §13.2). Plus locked v2 design constraint:
deterministic surface only (numeric / markup / slash-command — never
keyword classification). This is the strongest deferral story in the
spec.

**(c) Findings hanging?** **One:** the approval terminology kollision
from A3 — `permissionDecision` vs `[A]` — is now harder to confuse
because there is no `[A]`-detection code in v1 at all (§1 glossary
notes "v1 has no approval-detection layer"). Net: cut helps, doesn't
hurt.

### Cut B — MCP server deferred entirely (§8)

**(a) Prior review flagged?** **YES, comprehensively.** Agent A3
was entirely about MCP/state (5 ADRs, 1 DRIFT, 2 UNVERIFIED). Agent
B noted hallucination-check + sage-memory both depend on MCP.
Agent C GAP-3 specifically called out sage-memory MCP as HIGH risk
unaddressed. The cut is by far the biggest scope reduction.

**(b) v2 trigger documented?** **YES, three triggers** (§8 v2
promotion + §2 v2 promotion trigger): bash predicate complexity
ceiling (>80 LOC, >1s cold-start, language parsers needed); §6.2 v2
promotion (sage_record_approval needs Python's atomic file ops);
second port adopting MCP. Plus locked v2 location constraint
(`runtime/platforms/codex/mcp/` first, `runtime/mcp/server/` only on
second consumer). Strong.

**(c) Findings hanging?** **YES — three:**
1. **Sage-memory MCP (GAP-3) WORSENED.** Generated AGENTS.md instructs
   `sage_memory_search` per Rule 1A; Cut B removed the MCP runtime
   that would serve the call. The spec does NOT address how the
   generated AGENTS.md handles this contradiction. **This is the #1
   blocking issue.** Two options exist (neither in spec): (i) strip
   Rule 1A MCP references from generated AGENTS.md when no MCP server
   is configured; (ii) document a fallback to `.sage-memory/` markdown
   files (which the constitution already mentions as fallback) and
   make that the v1-only path. The spec needs to pick one or
   acknowledge the gap.
2. **A3 D6 deny-fail-closed contract** mentions MCP `required=true`;
   §13.1 R-1 marks it N/A in v1, but §5 "Hard policy" prose still
   says "v1 reintroduces an MCP server and its `required = true`
   deny-fail-closed contract" — this is **wrong as written** (says v1
   reintroduces; should say v2 reintroduces). Minor wording bug but
   real.
3. **A2 D9 timeout** moot per §11 D9 N/A — clean.

### Cut C — L5 client-side git hooks deferred (§2)

**(a) Prior review flagged?** Tangentially. ADR-1 trade-offs in §2
v1 layer scope decision references prior cut. Agents didn't push
back on this surface specifically.

**(b) v2 trigger documented?** **YES, binding:** outcome-harness data
showing L1+L2 bypass patterns (§2 + §13.2 "L1 bypass observed (v1)"
trigger). Concrete: agents disabling `.codex/hooks.json`, commits
landing without incident-log entries, `--no-verify` evasion observed.
v2 expansion: once MCP returns, trigger expands to "L1+L2 bypass" with
fourth condition added.

**(c) Findings hanging?** None directly. R-6 carries the accepted
risk. ADR-7 C5 precommit-log cross-check degrades cleanly to
"no precommit log available" mode (§4 Stage 8 v1 implication).

### Cut D — Hard tier-1 bypass deferred (§10)

**(a) Prior review flagged?** No — tier-1 was background context for
A4 profile mapping, not a flagged risk.

**(b) v2 trigger documented?** **PARTIAL.** §13.1 R-5 says baseline
measurement only in v1 (turn-audit.sh logs every `tier:` flip as
informational), but the explicit v2 promotion trigger isn't in §13.2
the way Cuts A/B/C are. §14 "Tier-1 trust marker" line says "field
design returns when v2 reintroduces hard tier-1 bypass alongside MCP
predicate" — coupled to Cut B v2 reactivation, but no quantitative
threshold like phase-jump rate has.

**(c) Findings hanging?** None directly. The cut is small-surface and
the soft-policy fallback is consistent with the rest of v1.

### Cuts mutual amplification

The four cuts compound: with no UPS (A) → no approval token → no MCP
tool to consume it (B) → no L5 to backstop bypassed L1 (C) → no hard
tier bypass to misuse (D). This is a **coherent v1 strategy**:
measurement-first, hardening-second. The risk is that the
measurement-only v1 produces no measurable signal because the agent
behaves correctly under soft policy — at which point v2 promotion
triggers never fire and the deferred work never returns. §13.2 doesn't
address this "negative result" case explicitly — recommended
non-blocking improvement (#NB-3).

## Blocking issues

These must be addressed before spec is signable:

### B1. Sage-memory MCP contradiction (GAP-3 worsened by Cut B)

**Where:** §4 Stage 3 composition item 2 (constitution placeholder
injection); §8 (MCP deferred entirely); generated AGENTS.md output.

**Problem:** The constitution text injected into generated AGENTS.md
contains Rule 1A: *"Before writing specs, plans, ADRs, or starting
an investigation, search sage-memory. Two searches minimum."* and
references `sage_memory_search` MCP tool. Cut B removed all MCP
infrastructure, so a Codex v1 agent following its own AGENTS.md
literally on first Standard+ workflow turn will either:
(a) attempt to call `sage_memory_search` → tool not found → error +
constitution violation, or
(b) skip the rule → constitution violation logged by no enforcement.

**Concrete change required:** Pick one and document in §4 Stage 3:

- **Option (i)** — strip Rule 1A MCP-tool references from generated
  AGENTS.md when no `[[mcp_servers]]` block is present in
  `.codex/config.toml`. Replace with: *"v1 has no Sage Memory MCP
  server; check `.sage-memory/` directory for past learnings if it
  exists."* The constitution already mentions `.sage-memory/`
  fallback — make this the v1 primary path. Generator-side: a flag
  or config check renders the v1-AGENTS.md variant.
- **Option (ii)** — add a note in generated AGENTS.md: *"sage-memory
  MCP server not configured in v1; Rule 1A is best-effort via
  filesystem fallback. v2 will reintroduce MCP server."* Less clean
  but lower-touch. Sets agent expectation correctly.

Document the choice in §4 Stage 3 or new subsection §4 Stage 3a
"Constitution variant rendering for v1".

### B2. Missing `core/gates/scripts/` copy (cap-bootstrap-state DRIFT)

**Where:** §4 Stage 7 (skills deploy) and §4 Stage 9 (`.sage/`
bootstrap).

**Problem:** Claude `bin/sage init` flow includes
`cp $SAGE_FRAMEWORK/core/gates/scripts/*.sh
<target>/.sage/gates/scripts/`. These scripts are how the Claude port
backstops engineering principles (test-before-code, no-silent-failures,
etc.) — they are runtime-callable from skills and from L5. Spec §4
Stage 9 only creates `.sage/gates/.gitkeep`; no script copy. Codex
projects bootstrapped via `bin/sage init --platform codex` will be
missing these scripts entirely, silently degrading any skill that
depends on them.

**Concrete change required:** Add to §4 Stage 9 (or as new Stage 9a):

> **Stage 9a — Deploy gates scripts.** Copy
> `$SAGE_FRAMEWORK/core/gates/scripts/*.sh` to
> `<target>/.sage/gates/scripts/`, set mode 0755. Claude parity:
> identical step in `bin/sage init` (`runtime/platforms/claude-code/
> setup/`). Codex deviations: none — gates scripts are
> platform-agnostic. If `$SAGE_FRAMEWORK/core/gates/scripts/` is
> empty (preset has no gates), skip with info message.

Plus add to §15.2 generator pipeline checklist:

> - [ ] All `core/gates/scripts/*.sh` copied to
>   `<target>/.sage/gates/scripts/` with mode 0755.

### B3. Constitution preset merge missing (cap-merge-constitution + GAP-2/GAP-4)

**Where:** §4 Stage 3 composition item 2.

**Problem:** Spec §4 Stage 3 says: *"replace
`__CONSTITUTION_PLACEHOLDER__` token in the source template with the
contents of `core/constitution.md`"*. This is a **single-source
injection**. Recon-claude-bootstrap documents that Claude port:

1. Reads `<target>/.sage/constitution.md` (user-overlay file, may or
   may not exist).
2. Extracts `extends:` field (e.g. `extends: enterprise`).
3. Merges contents of
   `$SAGE_FRAMEWORK/core/constitution/presets/${PRESET}.constitution.md`.
4. Injects merged result.

Without the merge, the 4 presets (base/startup/enterprise/opensource)
have no constitution-side effect — every Codex preset gets the same
baseline `core/constitution.md`. GAP-4 confirms: *"4 presets need
preset-specific constitution merge"*. GAP-2 confirms: *"`.sage/
constitution.md` user file + preset merge pattern from recon"*.

**Concrete change required:** Rewrite §4 Stage 3 composition item 2:

> 2. **Constitution merge + injection** — read
>    `<target>/.sage/constitution.md` (if present, extract
>    `extends:` field; default to preset name passed by Stage 2).
>    Merge contents of
>    `$SAGE_FRAMEWORK/core/constitution/presets/${PRESET}.constitution.md`
>    with `core/constitution.md` base (preset overlay wins on
>    conflicting rules; `.sage/constitution.md` user-overlay wins
>    over preset). Replace `__CONSTITUTION_PLACEHOLDER__` with merged
>    output. Claude parity: identical merge logic
>    (`runtime/platforms/claude-code/setup/generate-claude-code.sh:
>    419-473`).

Plus add to §15.2 checklist:

> - [ ] Generated `AGENTS.md` constitution section reflects active
>   preset (e.g. enterprise preset injects stricter rules visible in
>   diff against base preset).
