# Codex RealHarness runbook

This is the canonical runbook for agents running Codex RealHarness in this
repository. Read this file before running `runtime/platforms/codex/harness`.

## Required Profile

- Model: `gpt-5.4`
- Reasoning: `low`
- Service tier: default/implicit
- Target: dummy project generated by the harness
- Output/artifacts: under `~/tmp/`

## Artifact Location Rule

Put RealHarness outputs, transcripts, dummy targets, filtered scenario files,
and probe artifacts under `~/tmp/`. Do not put RealHarness run artifacts under
`.sage/work/`; `.sage/work/` may contain only the initiative artifacts that
summarize or reference the result.

## Service Tier Rule

Do not run RealHarness, probes, or QA tests with:

- `service_tier="fast"`
- `service_tier="flex"`

The correct RealHarness test tier is ordinary/default. Prefer no explicit
`service_tier` key in the effective config.

If local global config forces `service_tier="flex"`, do not inherit that config
for the harness run. Use an isolated clean `CODEX_HOME` or another safe config
path that preserves hook routing/trust but has no `service_tier` override.

If a hook-aware RealHarness run cannot be executed without `fast` or `flex`,
stop and report the blocker. Do not upgrade the tier to make the test pass.

## Hook Routing Rule

Do not use `--ignore-user-config` for hook-enforcement scenarios. In the current
Codex CLI routing, `--ignore-user-config` prevented project hook routing from
firing during the diagnostic probe.

The diagnostic probe showed:

- `SessionStart`, `PreToolUse`, and `Stop` fire when CLI hook routing is loaded.
- `PreToolUse` payload uses `tool_name: apply_patch`.
- Shell commands arrive as `PreToolUse` payloads with `tool_name: Bash`.
- JSONL transcript may show the edit as item type `file_change`; that does not
  mean the hook matcher should be `file_change`.
- Correct PreToolUse matchers for the current Codex CLI routing are
  `apply_patch` for file edits and `Bash` for shell commands.

## Recommended Command Shape

Use this shape only after preparing a clean hook-aware config that does not set
`service_tier`:

```bash
HARNESS_MODEL=gpt-5.4 \
HARNESS_REASONING=low \
HARNESS_TARGET_MODE=dummy-project \
HARNESS_OUT="$HOME/tmp/codex-realharness-<timestamp>" \
runtime/platforms/codex/harness/run-harness.sh
```

For scoped runs, use a wrapper or filtered harness mode that runs only the
requested prompt set. Do not mark omitted scenarios as passed.

## Expected Interpretation

Treat RealHarness evidence by type:

- Deterministic shell tests prove hook predicates and generated text.
- RealHarness proves live agent/runtime behavior only when hook routing is
  actually loaded.
- A transcript showing `file_change` is not proof that the PreToolUse matcher
  should be `file_change`; inspect the hook payload.
